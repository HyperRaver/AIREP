Google Trends Data Collection — Methodology Paragraph
======================================================
(For use in MSc thesis methodology section)


Google Trends data for 28 Bitcoin-related search terms was collected at weekly
granularity over an eight-year period (6 April 2018 to 27 March 2026) using
the pytrends Python library (v4.9.2), which interfaces with the unofficial
Google Trends API. Google Trends reports search interest as a relative index
scaled from 0 to 100, where 100 represents the peak popularity within the
queried timeframe and geographic scope (Google, 2024). Because this
normalisation is performed independently for each API request, raw values from
separate queries are not directly comparable — a value of 50 in one request may
correspond to a different absolute search volume than a value of 50 in another.

The 28 search terms were divided a priori into two sentiment groups — positive
and negative — each normalised independently to preserve within-group relative
magnitudes. The positive group comprises 14 terms associated with bullish
sentiment or acquisition intent (e.g., "invest in bitcoin," "bitcoin halving,"
"bitcoin etf," "diamond hands"), anchored to "buy bitcoin." The negative group
comprises 14 terms associated with bearish sentiment or divestment intent
(e.g., "bitcoin crash," "crypto winter," "short bitcoin," "bitcoin dead"),
anchored to "sell bitcoin." Anchors were selected from the study's own keyword
sets to avoid introducing extraneous variation.

Two methodological challenges arise. First, the Google Trends API normalises
each request independently, so keywords queried in separate requests receive
incompatible scales. Second, weekly-resolution data is only available for time
windows shorter than five years, necessitating two sequential pulls per group
to cover the full eight-year study period.

To address cross-keyword normalisation, a pairwise query design was adopted:
each keyword was queried individually alongside its group's anchor keyword in a
dedicated two-keyword request, yielding one request per keyword per time
period. This design ensures that the anchor keyword always retains a strong
signal in every request, avoiding the signal compression that can occur when
a high-volume keyword dominates a multi-keyword batch (Eichenauer, Indergand,
Martínez and Sax, 2022). For each pairwise request, a scaling factor was
computed as the median ratio of the anchor's values in a designated reference
pair to its values in the current pair, using only weeks where both values
exceeded zero. The keyword's values were then multiplied by this factor,
placing all keywords within a group on the anchor's native scale. The use of
median ratios reduces sensitivity to outlier weeks caused by sudden
news-driven spikes or integer rounding at low search volumes.

To address cross-period normalisation, the two pulls per group were configured
with a six-month temporal overlap (April 2022 to October 2022), yielding
approximately 26 shared weekly observations. A cross-period scaling factor was
computed as the median ratio of the anchor keyword's values in the overlap
window between the first and second period. All values from the second period
were then multiplied by this factor, and the non-overlapping portion was
appended to the first period's data. The standard deviation and range of the
overlap ratios are reported as diagnostics to assess calibration stability.

The resulting dataset contains weekly observations for all search terms on two
internally consistent relative scales — one for positive sentiment and one for
negative sentiment — each indexed to their respective anchor keyword's
historical peak (which corresponds to a value of 100). Because all keywords
within a group share this common reference point, values exceeding 100 are
both expected and meaningful: they indicate that a given search term's weekly
interest surpassed the anchor's peak. For instance, "bitcoin ETF" reached a
normalised value of approximately 373 during the week of its regulatory
approval (7 January 2024), indicating search interest roughly 3.7 times
greater than "buy bitcoin" at its historical maximum. This preserves
cross-keyword magnitude differences, which are central to the sentiment
analysis conducted in this study.

Google Trends assigns each weekly observation to the Sunday that begins the
reporting week (Sunday through Saturday). To align the sentiment data with
weekly financial returns, each Google Trends observation was matched to the
Friday closing price falling within the same reporting week, following the
approach of Da, Engelberg and Gao (2011).

All data collection scripts, normalisation parameters, and diagnostic outputs
are available in the study's code repository for reproducibility.
